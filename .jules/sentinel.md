## 2024-06-19 - [Stored XSS Protection via S3 Direct Serving]
**Vulnerability:** The application was serving user-uploaded files directly from S3 (via Fiber's `c.Context().SetBodyStreamWriter`) without restrictive `Content-Type` validations during upload, and without defense-in-depth headers on the download endpoint. This allowed malicious users to upload files (like SVG or HTML) and have them executed in the context of the application when another user accessed the media URL.
**Learning:** Because the backend proxies S3 objects directly and there is no intermediate CDN or Web Application Firewall (WAF) enforcing headers or stripping malicious files, the application itself MUST enforce both strict ingress validation (Content-Type whitelisting) and strict egress headers (`X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'; sandbox`).
**Prevention:** Always validate `Content-Type` against a strict whitelist on upload. On any endpoint serving user-generated files, enforce `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'; sandbox` to prevent browser execution of potentially malicious content.
