## 2024-06-23 - Predictable Filenames and Missing Content Security Policies in Media Uploads
**Vulnerability:** Found two issues in `internal/handlers/media_handler.go`: 1) Attachment filenames were being predictably generated using `time.Now().UnixNano()` rather than a cryptographically secure UUID, leading to potential file enumeration or overwrites. 2) The file download handler lacked Content-Security-Policy and X-Content-Type-Options, which combined with a missing Content-Type upload whitelist created a Stored XSS vector.
**Learning:** Security depends on a defense-in-depth strategy. Predictable IDs or names always open the door for IDOR or enumeration attacks. Lack of proper `Content-Type` validation on file uploads makes the entire storage bucket vulnerable to Stored XSS when files are served directly from the same domain without protective headers.
**Prevention:** Always use cryptographically secure IDs (e.g. `uuid.NewString()`) for uploaded files. Enforce strict allowlists for acceptable MIME types during upload. Always append `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'; sandbox` on file download endpoints to prevent browsers from executing potentially malicious content.
