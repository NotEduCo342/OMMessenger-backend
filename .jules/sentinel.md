## 2025-02-18 - Fix Stored XSS & Insecure File Naming in Media Proxy
**Vulnerability:** The `media_handler.go` endpoint for user-uploaded attachments (`UploadAttachment` and `GetMedia`) did not enforce strict `Content-Type` validation (allowing malicious uploads like HTML or SVG files), lacked necessary security headers (`X-Content-Type-Options`, `Content-Security-Policy`), and utilized predictable timestamp-based naming (`time.Now().UnixNano()`), making the endpoint vulnerable to Stored XSS, file enumeration, and unintended overwrites.
**Learning:** Even when utilizing S3 or external blob storage, the application layer proxying these files must enforce defense-in-depth protections. Missing these in a chat/messenger application is critical because media is automatically trusted and rendered in user contexts. Predictable names can also cause cross-tenant access or file corruption if timestamps overlap.
**Prevention:** Always whitelist `Content-Type` during the upload phase (do not rely solely on the extension), enforce strict security headers (`nosniff` and `sandbox` CSP) on any proxy download endpoint, and always use cryptographically secure UUIDs (`uuid.NewString()`) for stored filenames instead of predictable values.
