## 2024-06-29 - Predictable Filenames and Unrestricted File Uploads in Attachments
**Vulnerability:** Predictable filenames based on timestamps were used for attachment uploads, allowing attackers to enumerate and potentially overwrite files. Additionally, the lack of `Content-Type` whitelisting and missing defense-in-depth security headers during media downloads created a significant Stored XSS vulnerability.
**Learning:** Even if a cloud storage bucket is secured at the infrastructure level, failing to restrict uploaded file types (e.g., allowing HTML or SVG files with malicious scripts) and failing to enforce `Content-Security-Policy: sandbox` or `X-Content-Type-Options: nosniff` headers on the application backend exposes users to Stored XSS attacks when they view attachments.
**Prevention:** Always use cryptographically secure UUIDs (e.g., `uuid.NewString()`) for generating file names. Enforce a strict `Content-Type` whitelist during the upload phase, and always serve user-generated content with `Content-Security-Policy: default-src 'none'; sandbox` and `X-Content-Type-Options: nosniff` headers.
